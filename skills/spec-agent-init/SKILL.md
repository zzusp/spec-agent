# Spec agent init

## Trigger

Use when the user provides a new requirement and the caller AI needs a target directory plus active context before writing docs directly.

## Workflow

1. Read global memory and apply naming/constraint rules for `name`/`title`.
2. Run state-only init with `--name`, `--title`, `--desc`, `--state-only` (and `--project-mode` when known).
3. Create requirement directory, metadata, and clarification baseline; set `spec/.active`.

## Memory preload (must)

- Read `spec/00-global-memory.md` before any initialization decision.
- If the file defines naming conventions or mandatory constraints, apply them when generating `name/title`.

## Inputs

- `raw_requirement` (required)
- `name` (generated by caller AI)
- `title` (generated by caller AI)
- `project_mode` (`greenfield` or `existing`; if unknown use `auto` and infer from requirement text)

## Run

Use state-only init:
```bash
python scripts/spec_agent.py init --name <name> --title "<title>" --desc "<raw_requirement>" --state-only
```
If `project_mode` is known, pass it explicitly:
```bash
python scripts/spec_agent.py init --name <name> --title "<title>" --desc "<raw_requirement>" --state-only --project-mode <greenfield|existing>
```

## Output

- Create requirement directory and metadata.
- Set `spec/.active`.
- Create clarification baseline files only.

## Guardrails

- Do not generate analysis/PRD/tech/acceptance content in this skill.
